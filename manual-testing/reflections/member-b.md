## 1. What makes a test positive or negative?

A positive test checks whether the system accepts valid inputs, while a negative test checks whether the system correctly rejects invalid inputs.

## 2. Why can a negative test pass?

A negative test passes when the system correctly handles invalid input by rejecting it or displaying an appropriate validation message.

## 3. How did equivalence partitioning help you select data?

Equivalence partitioning helped me divide age inputs into valid and invalid groups. Instead of testing every possible age, I selected representative values such as 10, 30 and 90.

## 4. What did boundary testing help you investigate?

Boundary testing helped me identify errors that could occur around the minimum and maximum accepted ages. I tested values around 18 and 80 to check whether the form correctly handled the limits.

## 5. What did you choose to test during the open-ended activity, and why?

I chose to investigate decimal age input validation because previous activities mainly focused on whole-number ages. I wanted to find out whether the form accepts decimal values within and outside the permitted age range.

## 6. Did your observations lead to follow-up tests?

Yes. All three decimal inputs (18.5, 17.5 and 80.5) were rejected, which led me to question whether the form only supports whole-number ages. This raised a further question about whether the requirements should explicitly specify the accepted input format.
